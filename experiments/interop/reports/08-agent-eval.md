# 08: Which API style do coding agents get right first time? (hand-designed vs mirrored)

Controlled experiment, 144 single-shot attempts by fresh agents, 8 UI briefs, two API styles, three
documentation conditions. Everything is under `experiments/interop/eval/`; re-score with
`python3 eval/score.py` and `python3 eval/review/aggregate.py`.

## Headline

| Condition (n = 24 attempts per cell) | Style H type-clean | Style M type-clean | H rubric pass | M rubric pass |
|---|---|---|---|---|
| **gist**: 3-line primer, no types/docs | **0 / 24 (0%)**, 4.29 errors/attempt | **18 / 24 (75%)**, 0.25 | 65% | 83% |
| **cold**: 15-line primer, no types/docs | 24 / 24 (100%), 0.00 | 21 / 24 (88%), 0.12 | 90% | 86% |
| **with types**: 15-line primer + may read .d.ts/docs | 23 / 24 (96%), 0.04 | 24 / 24 (100%), 0.00 | 91% | 100% |

- With a full primer both styles are at ceiling on the type checker; the styles separate only when
  documentation is thin (gist) and on semantics the type checker cannot see.
- **The `$`-tag / static-const dialect was not a problem.** Across the 72 Style M attempts agents wrote
  217 `$` tags with **0** `$`-related type errors, even with the 3-line primer. One qualified static-const string
  out of 14 was wrong (`"TextInputType.emailAddress"` where the bare name is expected).
- **Style M's only repeated error is a place where the spike does not mirror Flutter**:
  `<Scaffold body={...}>` (6 of 72 attempts; the generator folds `body` into JSX children and drops the prop).
- **Style H's errors are the invented vocabulary**: 96 of its 104 type errors are
  `flex={{ direction: "row" | "column" }}` (the API wants `"horizontal" | "vertical"`), and 9 of its 10
  rubric failures under the full primer are one invented semantic (`grow={1}` is `FlexFit.loose` at
  runtime although the docs say it takes the remaining space).

Recommendation: make the mirrored surface the default generated surface; details in "Conclusion".

## Setup

### Sandboxes (`eval/sandbox-h`, `eval/sandbox-m`)

Both expose the module names `solid-fuse`, `solid-fuse/icons/material` and `solid-js` through
tsconfig `paths`, with `strict: true`, `jsx: "preserve"`, `skipLibCheck: false`; `tsc -p .` checks
`attempts/**/*.tsx`.

- **Style H**: the `src/types.ts`, `src/jsx.d.ts`, `src/widgets/**` and `src/icons/**` sources copied
  unmodified from the slivers worktree (View, Text, TextSpan, Icon, Image, GestureDetector, ScrollView,
  Stack, Positioned, TextField, tabs, 30+ slivers), with a trimmed `index.ts` and three-line type stubs
  for the controller modules. Docs for the "with types" condition: the slivers branch's
  `packages/docs/content/docs/widgets/**`.
- **Style M**: generated by `dart run tool/generate.dart --name evalm --docs none --widgets ...` in
  `eval/gen-copy` (a copy of `gen/`; the original is untouched): **66 widgets**, 866/964 parameters,
  96 KB `.d.ts` (Container, Padding, Row, Column, Expanded, Flexible, Spacer, Stack, Positioned, Text,
  Icon, GestureDetector, InkWell, ListView, SingleChildScrollView, TextField, the five Material
  buttons, Switch, Slider, Checkbox, Card, ListTile, SwitchListTile, Divider, AppBar, Scaffold,
  Image.network, CircleAvatar, Opacity, Align, Center, SizedBox, Wrap, the Animated* family, the Clip*
  family, DecoratedBox, ConstrainedBox, AspectRatio, FractionallySizedBox, Transform.translate/rotate,
  SafeArea, Chip, Material, Draggable, Visibility, ColoredBox, FittedBox, CircularProgressIndicator,
  ExpansionTile, IgnorePointer, Listener, Tooltip, PhysicalModel). Docs: a README with the wire
  conventions and one worked example (`sandbox-m/docs/README.md`, checked to compile).
- **Held equal across styles**: the same `solid-js` stub (`eval/shared/solid-js.d.ts`: createSignal,
  createMemo, createEffect, onCleanup, `For`, `Show`), and the same icons module (H's generated
  `icons/material.ts`; its `IconData` values are structurally valid for M's `IconData`, so icon naming
  is not a style difference). Solid's `Switch`/`Match` are exported in neither sandbox because the name
  collides with Flutter's `Switch`: a mirrored surface has to resolve that collision.

### Tasks (`eval/tasks/*.md`)

Plain-language briefs that name no component or prop of either API:

1. **settings**: title, two groups of labelled rows with on/off toggles (independent state), a 12..24 slider with live value, cards with uppercase grey headings, scrolls
2. **product-card**: 180-wide card, square cover image, 2-line ellipsised title, bold price left and star + rating right, radius 16, shadow, image corners clipped
3. **chat**: scrollable thread from props, shrink-wrapped bubbles max 260, mine right/blue and others left/grey, asymmetric corner radii, timestamp under each bubble
4. **login**: centered form max 320, email + obscured password fields, full-width button disabled until valid, conditional red helper text, `onSubmit` callback
5. **profile-header**: 160 banner, 96 circular avatar with white ring overlapping the banner by half, centered name/handle, three evenly distributed stats
6. **tags**: pills that wrap with 8 gaps, tap toggles selected style and a check icon
7. **draggable**: 300x300 bordered area, 80x80 square dragged with clamping, colour change while dragging, live delta/position text, `onDrop` on release
8. **collapsible**: header toggles a body whose height animates over ~250 ms, chevron rotates in sync, border + radius 12 with clipping, starts collapsed

### Agents and conditions

- Each attempt is a fresh headless agent (`claude -p`, model `claude-fable-5-2`, the same model as the
  experimenter; the in-process Agent tool was not available to this run, so the CLI was used
  instead). Agents ran outside the repository, so they did not see `AGENTS.md` or any repo file.
- The prompt (`eval/prompts/template.md`) is byte-identical across styles except for the primer and the
  reference path: three sentences of premise, the import paths, the primer, the brief, and the rules
  (write one file once, no `any`/`as`/`@ts-ignore`, no commands, no type checker).
- **cold**: only the `Write` tool; 15-line primer. **with types**: `Read`/`Grep`/`Glob`/`Write`, 15-line
  primer, may read the sandbox's `lib/` and `docs/` (mean 8 reads/searches per attempt in both
  styles). **gist** (added after the first two conditions hit the ceiling): only `Write`, 3-line primer.
- 3 attempts x 8 tasks x 2 styles x 3 conditions = **144 attempts**, run in shuffled order, 6 at a time.
  Transcripts (`eval/logs/`) confirm every agent wrote exactly once and no agent read outside its
  reference directory.

### Scoring

- **Types**: `tsc` over all attempts, each diagnostic categorised from its code, message and source
  line (`eval/score.py`, `eval/results/errors.json`).
- **Semantics**: one reviewer agent per (task, style, condition) scored the three files against a fixed
  rubric of 4 to 6 concrete criteria per task (`eval/review/rubrics.json`, 132 criteria per cell), given
  the runtime semantics of the style (for H read out of `dart/lib/src/widgets/view.dart` and
  `node.dart`; for M "Flutter's rules apply") and told to ignore type errors and trace constraints.
  Verdicts are in `eval/reviews/`, aggregated in `eval/results/semantic.json`. I read every non-pass
  verdict and spot-checked files of both styles against them.

## The primers

Style H, 361 words (`eval/prompts/primer-h.md`):

```
1. The layout container is `<View>`; there are no Row/Column components. Lay out children with the `flex` prop: `<View flex={{ direction: "horizontal", gap: 8, align: "center", justify: "spaceBetween" }}>` (direction defaults to "vertical"; `align` is the cross axis, `justify` the main axis, `expand: true` fills the main axis).
2. A child takes the remaining space of a flex parent with `grow={1}` on its own `<View>` (optionally `fit="loose"`).
3. `<View>` also takes: padding, margin, width, height, minWidth/maxWidth/minHeight/maxHeight, aspectRatio, alignment ("center", "topLeft", "bottomRight", ...), opacity, visible, ignorePointer, clipBehavior ("antiAlias"), `transform={{ rotate, scale, translateX, translateY }}` (rotate in radians).
4. padding/margin are a number (all sides), `{ horizontal, vertical }`, or `{ top, left, right, bottom }`.
5. Backgrounds go in `decoration`: `decoration={{ color: "white", borderRadius: 12, border: { width: 1, color: "#E0E0E0" }, shadow: [{ blurRadius: 8, color: "#0002", offsetY: 2 }], gradient: { type: "linear", colors: [...], begin: "topLeft", end: "bottomRight" }, shape: "circle" }}`; borderRadius may be `{ topLeft, topRight, bottomLeft, bottomRight }`.
6. Colors are names ("red", "white", "grey", "transparent", ...), CSS hex "#RGB" / "#RRGGBB" / "#RRGGBBAA", or `{ r, g, b, a }`.
7. `<Text>` has its style props flattened onto the element: `<Text fontSize={18} fontWeight="bold" color="#333" maxLines={2} overflow="ellipsis" textAlign="center">hi</Text>`; fontWeight is 100..900 or "regular" | "medium" | "semiBold" | "bold".
8. A `<Text>` may contain `<TextSpan>` runs and other elements as children; non-span children flow inline with the text and wrap with it.
9. `<Icon data={star} size={24} color="amber" />` with `import { star } from "solid-fuse/icons/material"` (Flutter's icon names, camelCase).
10. `<Image src="https://..." width={80} height={80} fit="cover" borderRadius={8} />`; `<ScrollView>` scrolls its children (scrollDirection, padding, flex).
11. `<Stack alignment="center">` layers its children; `<Positioned top left right bottom width height>` places one child inside a Stack.
12. `<GestureDetector onTap={...} onPanUpdate={(e) => ...}>` uses Flutter's callback names; details are flat: e.x, e.y, e.localX, e.localY, e.dx, e.dy (delta), e.vx, e.vy (velocity).
13. `<TextField value={v()} placeholder="Email" obscureText keyboardType="email" onChanged={(text) => ...} decoration={{ border: "outline", labelText: "Email" }} />`.
14. There are no Button, Switch, Slider or animated widgets: compose them from View, GestureDetector and signals.
15. Every prop is reactive; children are ordinary JSX children; every element that has children accepts `flex`.
```

Style M, 372 words (`eval/prompts/primer-m.md`):

```
1. Components are Flutter's Material widgets under the same names, with the constructor's parameters as props: `<Container>`, `<Row>`, `<Column>`, `<Expanded>`, `<Padding>`, `<SizedBox>`, `<Stack>`, `<Positioned>`, `<Text>`, `<ListView>`, `<Scaffold>`, `<ElevatedButton>`, `<Switch>`, `<Slider>`, `<Card>`, `<ListTile>`, `<Wrap>`, `<AnimatedContainer>`, `<ClipRRect>`, ...
2. `child` / `children` are JSX children; other widget-typed parameters are JSX-valued props: `<ListTile title={<Text>Hi</Text>} trailing={<Switch value={on()} onChanged={setOn} />} />`. Text's string is its JSX child.
3. Named widget constructors are concatenated: `Image.network(url)` is `<ImageNetwork src={url} />`, `Transform.rotate` is `<TransformRotate angle={...}>`.
4. Enums are the member name as a string: `mainAxisAlignment="spaceBetween"`, `overflow="ellipsis"`, `fit="cover"`, `clipBehavior="antiAlias"`.
5. Value classes are plain objects keyed by the constructor's parameter names (positional ones too): `style={{ fontSize: 18, fontWeight: "bold", color: "#333" }}`, `offset={{ dx: 0, dy: 2 }}`, `constraints={{ maxWidth: 300 }}`.
6. A named constructor is selected with a `$` tag: `padding={{ $: "symmetric", horizontal: 16, vertical: 8 }}`, `{ $: "only", left: 8 }`, `border={{ $: "all", color: "#ddd", width: 1 }}`.
7. Where the parameter type is abstract, the concrete subclass is the `$` tag: `decoration={{ $: "BoxDecoration", color: "white", borderRadius: 12, boxShadow: [{ color: "#0002", blurRadius: 8, offset: { dx: 0, dy: 2 } }] }}`, `gradient={{ $: "LinearGradient", colors: [...] }}`, `shape={{ $: "RoundedRectangleBorder", borderRadius: 8 }}`.
8. Static constants are strings: bare on the type itself (`alignment="center"`, `fontWeight="w600"`), qualified on a namespace class (`curve="Curves.easeInOut"`, `color="Colors.black54"`).
9. Shorthands: Color also takes names ("red", "white", "grey", "transparent", ...) and CSS hex "#RGB" / "#RRGGBB" / "#RRGGBBAA"; EdgeInsets, BorderRadius and Radius take a number (all sides); Duration takes milliseconds; FontWeight takes 100..900.
10. No method calls or indexing on values: there is no `Colors.grey[300]`, `.withOpacity()` or `ElevatedButton.styleFrom()`; use hex colors and plain objects.
11. `<Icon icon={star} size={24} color="amber" />` with `import { star } from "solid-fuse/icons/material"` (Flutter's icon names, camelCase).
12. Callbacks keep Flutter's names and get Flutter's details objects as plain data: `onPanUpdate={(d) => d.delta.dx}`, `onChanged={(v) => ...}`; `onPressed={null}` disables a button. BuildContext is never passed.
13. `<TextField decoration={{ labelText: "Email", border: { $: "OutlineInputBorder" } }} obscureText keyboardType="emailAddress" onChanged={(text) => ...} />`; controllers are not needed.
14. Builders (`ListView.builder`, `LayoutBuilder`) are not available: render lists as children with `<For>` or `.map`.
15. Every prop is reactive; implicitly animated widgets (`<AnimatedContainer duration={300}>`) animate when their props change.
```

Gist primers (109 and 116 words):

```
H
1. Components: `<View>` is the only layout container (there is no Row/Column: use its `flex={{ direction, gap, align, justify }}` prop, `grow={1}` on a child, and `decoration={{ color, borderRadius, border, shadow }}` for backgrounds), plus `<Text>` (style props flattened onto it: fontSize, fontWeight, color), `<Icon data>`, `<Image src>`, `<ScrollView>`, `<Stack>`, `<Positioned>`, `<GestureDetector>` and `<TextField>`.
2. Colors are names or CSS hex strings; padding/margin are a number or `{ horizontal, vertical, top, left, right, bottom }`; gesture details are flat (`e.dx`, `e.localX`); icons are imported by name (`import { star } from "solid-fuse/icons/material"`).
3. There are no Button, Switch, Slider or animated widgets: compose them from View, GestureDetector and signals.

M
1. Components are Flutter's Material widgets 1:1: same names, the constructor's parameters as props, `child` / `children` as JSX children, other widget parameters as JSX-valued props, named constructors concatenated (`Image.network` is `<ImageNetwork src>`).
2. Dart values are plain data: enums and static constants are strings ("spaceBetween", "Curves.easeInOut"), classes are objects keyed by constructor parameter name, with `$` selecting a named constructor or a subclass (`{ $: "symmetric", horizontal: 8 }`, `{ $: "BoxDecoration", color: "white" }`); no method calls on values.
3. Colors also take names or CSS hex strings, EdgeInsets/BorderRadius a number, Duration milliseconds; icons are imported by name (`import { star } from "solid-fuse/icons/material"`, `<Icon icon={star}>`); callbacks get Flutter's details objects as plain data.
```

## Limits

- **Small n.** Three attempts per task per cell; 24 per cell. Differences of one or two attempts
  (for example 88% vs 100% type-clean in cold) are not significant. The large effects (0 / 24 vs 18 / 24
  in gist; 0 `$` errors in 217 uses) are.
- **One model family.** Writers, reviewers and the experimenter are the same model. A weaker or
  differently trained agent may know Flutter less well, and the reviewers may share the writers' blind
  spots. Nothing was rendered: semantic verdicts are reasoned, not observed.
- **Type errors are a proxy, and the two type surfaces are not equally strict.** H types `children` and
  `JSX.Element` as `any` and colours as any string, so H's clean rate is an upper bound (the reviewers
  found a spread `rotate` prop and a root `grow` that `tsc` passed). Re-checking H with colour strings
  constrained to names and `#hex` (`eval/sandbox-h-strict`) flagged no invalid colour literal, only
  `string`-typed palette variables. M's types are generated with the Dart decoders, but the decoders
  were not exercised here.
- **Style and coverage are confounded.** H has no Switch, Slider, button, Wrap or animation; part of
  M's advantage is having the widget, not how it is spelled. That is still the practical comparison:
  the mirrored surface gets coverage from the generator for free.
- **The primers decide a lot, and I wrote them.** The full primers pre-empt the likely errors of each
  style (M: "no `Colors.grey[300]`, no `.withOpacity()`"; H: the exact `flex` vocabulary). The 15-line H
  primer also repeated the docs' wrong description of `grow`. The gist primers are the closer test of
  "what does the agent already know", and there the H primer simply cannot carry an invented vocabulary.
- **Two spike behaviours are not pure mirroring** and were left as generated: `flex` on single-child
  widgets (unused by every agent) and `Scaffold.body` as children (the main M error).
- **One sandbox artefact was fixed before final scoring**: the shared `Show` stub rejected several JSX
  children under M's stricter `JSX.Element`; the stub now accepts an array in both sandboxes. Tasks are
  ordinary Material-shaped screens; no slivers, navigation, custom paint or handles were tested.

## Conclusion

**Make the mirrored surface (Style M) the default generated surface.**

1. The hypothesis holds: agents write Flutter's names, parameters and widget choices from memory. With
   three lines of documentation M was type-clean in 75% of attempts and H in none; with the types
   available M was 24 / 24 on both the type checker and the rubric.
2. The counter-hypothesis did not hold for this model: the `$` tag was learned from two examples and
   used 217 times without an error. Static-const strings produced one error. The risk in M is not the
   encoding but **any place the surface departs from Flutter**.
3. H can be taught (15 lines get it type-clean), but every invented name is a fact the agent must be
   told, and invented semantics fail silently: H's errors were CSS and Flutter vocabulary leaking in
   (`"row"`, `"emailAddress"`, `"w600"`, `offset`, `height`), plus `grow`.

**Codecs and aliases that would remove the observed Style M errors** (in order of frequency):

1. Keep every Flutter parameter name even when it is also mapped to JSX children: accept
   `<Scaffold body={...}>` as well as children (6 of the 10 M errors). As a generator rule: a children
   hint adds an alternative, it never removes the prop.
2. Accept the qualified form of a static constant wherever the bare one is accepted
   (`"TextInputType.emailAddress"`, and by the same rule `"FontWeight.w600"`, `"Alignment.center"`,
   `"EdgeInsets.zero"`), so the agent never has to know where a constant is declared.
3. Icon names: export snake_case aliases (`expand_more`) next to the camelCase ones, or accept
   `"Icons.expand_more"` strings as `IconData`. This error is independent of style (3 occurrences).
4. Decide the `Switch` name collision with Solid's control flow in favour of Flutter's widget (take
   Solid's `Switch`/`Match` from `solid-js` or rename them); every settings attempt needed the widget.
5. Keep the existing codecs: hex and named colours, numeric EdgeInsets/BorderRadius/Radius, millisecond
   durations and numeric FontWeight were used in every M file with no errors.

**Style H ideas worth keeping as a thin layer on top:**

- The friendly value codecs above (already in the spike) and the tree-shakeable icons module.
- Flat, documented escape hatches that cost nothing when ignored: `Image`'s auto-detected `src` and
  `borderRadius`, and a composite `View` for people who prefer it. If `View`/`flex` stays, it should be
  written in terms of the generated widgets, accept `"row"`/`"column"` as aliases of
  `"horizontal"`/`"vertical"`, and make `grow` tight by default (or fix the docs; today the docs and
  `view.dart` disagree, which is worth fixing on main regardless of this decision).
- Where H renames a Flutter value, accept Flutter's spelling too (`"emailAddress"`, `"w600"`,
  `offset: { dx, dy }`, `height` on Text): those are exactly the errors H provoked.
- Do not carry over `flex` on generated single-child widgets: no agent used it in 72 attempts.
