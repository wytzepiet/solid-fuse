Flutter's designs live in their own packages now (`material_ui`, `cupertino_ui`), and so do Fuse's:

| Package | What it has |
|---|---|
| `@solid-fuse/material` | `MaterialApp`, `Scaffold`, `AppBar`, `Button`, `IconButton`, `FloatingActionButton`, `Switch`, `Checkbox`, `Radio`, `Slider`, `TextField`, `Card`, `ListTile`, `Divider`, `Chip`, `Badge`, `ProgressIndicator`, `NavigationBar`, `Dialog`, `BottomSheet`, `materialPage`, `Icons`, `Colors` |
| `@solid-fuse/cupertino` | `CupertinoApp`, `PageScaffold`, `NavigationBar`, `Button`, `Switch`, `Checkbox`, `Radio`, `Slider`, `TextField`, `ActivityIndicator`, `SegmentedControl`, `ListSection`, `ListTile`, `Dialog`, `ActionSheet`, `cupertinoPage`, `CupertinoIcons`, `CupertinoColors` |
| `@solid-fuse/adaptive` | `AdaptiveApp`, `Button`, `Switch`, `Checkbox`, `Slider`, `TextField`, `ProgressIndicator`, `Dialog`: Cupertino on iOS and macOS, Material elsewhere |

```bash
bun add @solid-fuse/material
bunx fuse link
```

Each package also brings all of its Flutter library to JS through [generation](/docs/extending/generating): `#fuse/material_ui` and `#fuse/cupertino_ui` have every widget, for what the components leave out.

## The shape of the components

The components are thin layers over the generated widgets, with the same rules as [core's](/docs/building/core-widgets):

- State is a controlled pair: `<Switch value={on()} onChange={setOn} />`, `<Dialog open={open()} onOpenChange={setOpen}>`.
- Events are `on` + verb: `onPress`, not `onPressed`. `disabled` disables.
- Variants are string unions: `<Button variant="tonal">`, `<Card variant="outlined">`.
- A slot that takes text takes a string (`title="Inbox"`); a slot that takes an icon takes the constant (`leading={Icons.inbox}`). Both take any element too.
- Dialogs and sheets are components with `open`. They take no space where they sit.

## Material

```tsx
import { MaterialApp, Scaffold, AppBar, Button, Icons, NavigationBar, NavigationDestination } from "@solid-fuse/material";
import { Navigator } from "solid-fuse";

render(() => (
  <MaterialApp theme={{ seedColor: "#2563eb" }} themeMode="system">
    <Navigator initialPage={() => <Home />} />
  </MaterialApp>
));

function Home() {
  const [tab, setTab] = createSignal(0);
  return (
    <Scaffold
      appBar={<AppBar title="Home" actions={<IconButton icon={Icons.search} />} />}
      bottomNavigationBar={
        <NavigationBar selected={tab()} onSelect={setTab}>
          <NavigationDestination icon={Icons.home} label="Home" />
          <NavigationDestination icon={Icons.person} label="Profile" />
        </NavigationBar>
      }
    >
      <Button onPress={save} icon={Icons.save}>Save</Button>
    </Scaffold>
  );
}
```

`theme` is a theme in brief (`seedColor`, `brightness`, `fontFamily`, `contrast`) or a full generated `ThemeData({...})` from `#fuse/material_ui/ThemeData`. A brief theme gets its dark version for free.

A dialog:

```tsx
<Dialog
  open={open()}
  onOpenChange={setOpen}
  title="Discard draft?"
  actions={[<Button variant="text" onPress={() => setOpen(false)}>Cancel</Button>]}
>
  The draft will be gone.
</Dialog>
```

## Cupertino

```tsx
import { CupertinoApp, PageScaffold, NavigationBar, ListSection, ListTile, CupertinoIcons } from "@solid-fuse/cupertino";

<CupertinoApp theme={{ primaryColor: "#ff2d55" }}>
  <Navigator initialPage={() => (
    <PageScaffold navigationBar={<NavigationBar title="Settings" />}>
      <ListSection header="Network">
        <ListTile leading={CupertinoIcons.wifi} title="Wi-Fi" additionalInfo="Home" onPress={openWifi} />
      </ListSection>
    </PageScaffold>
  )} />
</CupertinoApp>
```

`SegmentedControl` takes its segments as data: `options={[{ value: "day", label: "Day" }, ...]}`.

## Adaptive

`@solid-fuse/adaptive` has the components whose meaning is the same on both platforms. Each renders the Cupertino one on iOS and macOS and the Material one elsewhere. `AdaptiveApp` is a Material app on every platform (Material pages slide the iOS way on iOS), so components from either package work inside it.

```tsx
import { AdaptiveApp, Switch, Dialog } from "@solid-fuse/adaptive";

<Dialog open={open()} onOpenChange={setOpen} title="Delete?" actions={[
  { label: "Cancel", onPress: close },
  { label: "Delete", destructive: true, onPress: remove },
]} />
```

### Previewing the other platform

`platform` makes the whole app behave like another platform: the adaptive components' design and Flutter's own platform feel (page transitions and the iOS back swipe, scroll physics, text selection, typography). It's reactive, so a debug toggle can flip a running app; screens already showing restyle in place and keep their state.

```tsx
const [platform, setPlatform] = createSignal<TargetPlatform>();

<AdaptiveApp theme={{ seedColor: "#2563eb" }} platform={platform()}>
  <Navigator initialPage={() => <Home />} />
</AdaptiveApp>

// somewhere in a debug menu
<Button onPress={() => setPlatform(platform() === "iOS" ? "android" : "iOS")}>Switch platform</Button>
```

Leave it `undefined` for the device's platform. `MaterialApp` takes the same `platform` (the feel only, it has no adaptive components). To restyle only the components, pass `design` instead, or wrap a subtree in `<AdaptiveProvider design="cupertino">`, say for a side-by-side preview. `useDesign()` returns the design in effect, as an accessor, for code of your own that branches on it.

## Mixing

Cupertino widgets work under `MaterialApp`, and core's widgets work under every root. Material widgets need a Material ancestor: use them under `MaterialApp` or `AdaptiveApp`.
