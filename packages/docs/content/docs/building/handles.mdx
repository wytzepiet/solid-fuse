Some Flutter patterns are imperative — you can't express "scroll to offset 500" or "focus this input" as a prop. A **handle** bridges this gap: a persistent Dart object backing a JS-side reference that you can call methods on and read reactive state from.

Handles come from your app's generated Flutter layer, `#fuse/flutter`: every Flutter controller there has a `createX` (see [Controllers: createX](/docs/extending/generating#controllers-createx)). Core's widgets take the same ones, so there is one `FocusNode` and one `ScrollController`, with everything Flutter's have.

## ScrollController

Pass `createScrollController()` to a `ScrollView` (or a generated `ListView`) and drive it. Its `offset()` is a signal that follows the scroll.

```tsx
import { For } from "solid-js";
import { Pressable, ScrollView, Text, View } from "solid-fuse";
import { createScrollController } from "#fuse/flutter";
import { easeOut } from "#fuse/flutter/Curves";

function ScrollableList() {
  const scroll = createScrollController();

  return (
    <View layout={{ expand: true }}>
      <View layout={{ direction: "horizontal", gap: 8 }} padding={8}>
        <Pressable onPress={() => scroll.animateTo(0, { duration: 300, curve: easeOut })}>
          <View padding={8} decoration={{ color: "blue", borderRadius: 4 }}>
            <Text color="white">Top</Text>
          </View>
        </Pressable>
        <Text>Offset: {Math.round(scroll.offset() ?? 0)}</Text>
      </View>

      <ScrollView controller={scroll} flex={1}>
        <View layout={{ gap: 4 }} padding={16}>
          <For each={Array.from({ length: 100 }, (_, i) => i)}>
            {(i) => <Text>Item {i}</Text>}
          </For>
        </View>
      </ScrollView>
    </View>
  );
}
```

`createScrollController({ initialScrollOffset: 200 })` starts somewhere else. The methods are Flutter's: `jumpTo(offset)`, `animateTo(offset, { duration, curve })` (duration in ms), and state such as `offset()` and `hasClients()`.

## FocusNode

Pass `createFocusNode()` to a text field (core's `TextInput`, or a design package's `TextField`) or a `Pressable`. `hasFocus()` is a signal.

```tsx
import { Pressable, Text, TextInput, View } from "solid-fuse";
import { createFocusNode } from "#fuse/flutter";

function FocusDemo() {
  const focus = createFocusNode();

  return (
    <View layout={{ gap: 6 }}>
      <TextInput focusNode={focus} placeholder="Type here" />
      <Text>hasFocus = {focus.hasFocus() ? "true" : "false"}</Text>
      <Pressable onPress={() => focus.requestFocus()}>
        <Text color="blue">Focus the field</Text>
      </Pressable>
      <Pressable onPress={() => focus.unfocus()}>
        <Text color="blue">Unfocus</Text>
      </Pressable>
    </View>
  );
}
```

## Lifetime

A handle made inside a component lives as long as that component; one made outside any owner lives until JS lets go of it. `dispose()` ends it early.

## Building your own

You can create handles for any persistent native Dart object — animation controllers, page route observers, native plugin instances. See [Creating handles](/docs/extending/creating-handles) for the full pattern.
