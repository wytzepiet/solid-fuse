---
title: Icons
description: Material and Cupertino icons as constants the build can shake
---

`Icon` draws one glyph. Its `icon` is a constant from a design package: `Icons` from `@solid-fuse/material`, `CupertinoIcons` from `@solid-fuse/cupertino`. The names are Flutter's.

```tsx
import { Icon } from "solid-fuse";
import { Icons } from "@solid-fuse/material";

<Icon icon={Icons.search} size={24} color="#111827" />
```

```tsx
import { CupertinoIcons } from "@solid-fuse/cupertino";

<Icon icon={CupertinoIcons.heart} />
```

An icon constant is the Dart constant's name (`"Icons.search"`), not a code point. The bundle keeps only the icons it uses, and `fuse build` keeps only their Dart side, so Flutter's icon tree shaking keeps working: the app ships the glyphs it uses, not the whole font.

## Reactive props

Every prop is reactive.

```tsx
const [liked, setLiked] = createSignal(false);

<Icon icon={liked() ? Icons.favorite : Icons.favorite_border} color={liked() ? "#EF4444" : "#6B7280"} />
```

## Props

| Prop | Type | Description |
|---|---|---|
| `icon` | `IconData` | The glyph: `Icons.home`, `CupertinoIcons.add` |
| `size` | `number` | Width and height in logical pixels |
| `color` | `Color` | See [Values](/docs/building/ui-and-layout#values) |
| `semanticLabel` | `string` | Read by screen readers |
| `fill`, `weight`, `grade`, `opticalSize` | `number` | Variable-font axes (Material Symbols) |
| `applyTextScaling` | `boolean` | Scale with the platform text size |

## Icons in other widgets

The design packages' slots that take an icon (`leading`, `prefixIcon`, a button's `icon`) take the constant itself, or any element:

```tsx
<TextField label="Search" prefixIcon={Icons.search} />
<ListTile leading={<Icon icon={Icons.wifi} color="#16A34A" />} title="Wi-Fi" />
```

## Your own icon font

Export your icons from your app's `dart/lib/fuse.dart` as a class of `IconData` constants; [generation](/docs/extending/generating) turns them into constants like `Icons`.
