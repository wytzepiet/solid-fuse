title: Creating Handles
description: Build imperative Dart objects accessible from JS
---

A **handle** is a persistent native Dart object (controllers, managers, connections) that JS can call methods on and receive state updates from. Use one when you need imperative control that doesn't fit the declarative widget model — anything backed by a long-lived Dart object behind a JS-side reference. The built-ins `createScrollController` and `createFocusNode` are thin wrappers around the same primitives.

## When to create a handle

- You need a Dart object that persists across renders (`ScrollController`, `FocusNode`, `AnimationController`)
- JS needs to call methods on it (`jumpTo`, `requestFocus`, `forward`)
- Dart needs to push state back to JS reactively (`scrollOffset`, `hasFocus`, `animationValue`)

## JS side: extend `FuseHandle`

A handle is a class extending `FuseHandle<K>`, where `K` is the node type string. The base class allocates the backing node, emits the create op, and gives you a protected `call` and a public `dispose`. Subclasses declare the node type to `super`, expose typed methods, and store any reactive signals as fields.

```tsx
import { createSignal } from "solid-js";
import { FuseHandle } from "solid-fuse";

export class FocusNode extends FuseHandle<"focusNode"> {
  readonly hasFocus: () => boolean;

  constructor() {
    const [hasFocus, setHasFocus] = createSignal(false);

    // setHasFocus is a function — it's stored in the JS handler map and
    // exposed to Dart, which calls it whenever the FocusNode's value changes.
    super("focusNode", { setHasFocus });

    this.hasFocus = hasFocus;
  }

  focus() {
    return this.call("focus");
  }

  unfocus() {
    return this.call("unfocus");
  }
}
```

### Why a class

`FuseHandle` is a class, not a `{ node, call, dispose }` factory object, so the handle's *type* is nominal: a `FocusNode` is distinguishable from a `ScrollController` even though both structurally carry a `node`. That distinction is real at runtime (`instanceof`) and at the type level (the prototype chain plus the private `#disposed` field), which is what lets a widget prop demand a *specific* kind of handle. It also keeps the wire shape tight — methods live on the prototype, so when a handle is passed as a prop the instance's only own property is `node`, and that's all that crosses the bridge.

### node

A `FuseNode<K>` reference, set by the base constructor. Widgets that accept the handle (like `<TextField focusNode={focus} />`) read this to serialize a `_node: <id>` ref over the bridge. The `K` type parameter (`"focusNode"` here) discriminates handle kinds at prop sites.

### call(method, value?, options?)

`protected` — call it from your subclass methods. Sends an imperative RPC to the Dart handle and returns a promise that resolves with the Dart handler's return value.

```tsx
this.call("animateTo", { offset: 500, duration: 300 });
```

Default timeout is 30 seconds. Pass `{ timeout: 0 }` for long-running native operations. It's protected so the raw RPC surface stays off the public API — consumers call your typed wrappers (`animateTo`, `focus`) instead.

### dispose()

Public and idempotent — emits the dispose op, guarded so repeated calls are no-ops. Safe to call manually even when a factory has already wired it to owner cleanup (see below).

### Pushing state from Dart with setters

There's no built-in "state signal" primitive — state from Dart flows through ordinary function props. Pass a setter from `createSignal` to `super(...)`; the Dart side invokes it whenever the value changes:

```tsx
const [hasFocus, setHasFocus] = createSignal(false);
super("focusNode", { setHasFocus });
this.hasFocus = hasFocus;

// In JSX — subscribes, re-renders when Dart pushes
<Text>{hasFocus() ? "Focused" : "Blurred"}</Text>
```

The function is stored in the JS handler map and surfaces on the Dart side as a callable on the node. Functions are not serialized — only a marker that one exists.

### Plain-value props go inline

Plain (JSON-serializable) props passed to `super(...)` land inline in the `create` op so the Dart factory can read them immediately at construction time:

```tsx
super("scrollController", {
  initialScrollOffset: 120,   // read by Dart constructor
  setScrollOffset,            // setter callback
});
```

On the Dart side, the constructor sees `node.double('initialScrollOffset')` populated before `object` is built.

## The `create*` factory: lifecycle

Constructing a handle with `new` does **not** tie it to a reactive owner — you own `dispose()`. The Solid-flavored entry point is a small `create*` factory that constructs the handle and wires owner-scoped auto-disposal, mirroring `createSignal`/`createMemo`:

```tsx
import { getOwner, onCleanup } from "solid-js";

export function createFocusNode(): FocusNode {
  const node = new FocusNode();
  if (getOwner()) onCleanup(() => node.dispose());
  return node;
}
```

This split is deliberate:

- `createFocusNode()` — auto-disposes with the owning component. The common case.
- `new FocusNode()` — manual lifecycle. For module-level singletons or code outside any owner; call `dispose()` yourself.

<Callout type="info">
Wrap the disposal in an arrow (`() => node.dispose()`), not a bare `node.dispose`
reference — `dispose` reads `this`, so a detached reference would lose its receiver.
</Callout>

## Dart side: `FuseHandle<T>`

Implement `FuseHandle<T>` where `T` is the type of the wrapped native object. The base class gives you the node, a `call` hook, and a `dispose` hook.

```dart title="dart/lib/src/handles/focus_node.dart"
import 'package:flutter/widgets.dart';
import 'package:solid_fuse/solid_fuse.dart';

class FuseFocusNode extends FuseHandle<FocusNode> {
  FuseFocusNode(super.node) : object = FocusNode() {
    object.addListener(
      () => node.callback('setHasFocus')?.call(object.hasFocus),
    );
  }

  @override
  final FocusNode object;

  @override
  Future<dynamic> call(String method, dynamic value) async {
    switch (method) {
      case 'focus':
        object.requestFocus();
      case 'unfocus':
        object.unfocus();
      default:
        throw StateError('Unknown focusNode method: $method');
    }
    return null;
  }

  @override
  void dispose() => object.dispose();
}
```

### object

The wrapped native Dart object — `FocusNode`, `ScrollController`, a route, whatever. Initialized in the constructor (use `final` if you need listener wiring at creation time) or `late final` for purely lazy resources.

`object` is what `node.handle<T>('propName')` returns on the consuming widget side, so it's the value other widgets receive when you pass `controller={ctrl}`.

### call(method, value)

Handles imperative RPCs from JS. The return value is forwarded as the resolution of the JS `call(...)` promise.

### dispose()

Called when the node is removed from the registry (JS `dispose()` is called, or the owning component unmounts). Release native resources here.

### Calling JS setters from Dart

State updates back to JS go through `node.callback(name)`, which returns a callable if the prop was set, or `null` otherwise:

```dart
node.callback('setScrollOffset')?.call(controller.offset);
```

The callback name is the same string you passed to `super(...)` on the JS side.

## How handle references resolve

When JS sets a widget prop to a handle (like `<ScrollView controller={scroll}>`), the renderer reads `scroll.node` and serializes the reference as `_node: <id>`. Dart hydrates it back into a `FuseNode` reference, and widgets pull the wrapped object out with `node.handle<T>(propName)`:

```dart
final controller = node.handle<ScrollController>('controller');
return SingleChildScrollView(controller: controller, child: ...);
```

The `node.handle<T>` accessor null-checks the type — if a `FocusNode` ends up on a `controller` prop expecting `ScrollController`, you get `null` (with a debug-mode warning) instead of a crash.

## Cleanup

Handles created with a `create*` factory inside a Solid reactive context (inside a component or `createRoot`) automatically dispose when the owner is cleaned up:

```tsx
function MyComponent() {
  const scroll = createScrollController(); // auto-disposes on unmount
  return <ScrollView controller={scroll} />;
}
```

<Callout type="warn">
A handle built with `new` (or created **outside** a reactive context) won't auto-dispose. Call `dispose()` yourself if it manages native resources.
</Callout>

## Registration

```dart
runtime.registerHandle('focusNode', FuseFocusNode.new);
```

The lifecycle: on `create` op the runtime instantiates the handle, stores it on the node. On `_handleCall` channel messages, it delegates to `handle.call(...)`. On `dispose` op, it calls `handle.dispose()`.

## Navigator observers

A `NavigatorObserver` is a handle whose wrapped Dart object hooks into route changes (hero flights, route analytics). Core stays observer-agnostic — it only knows "a handle can supply a `NavigatorObserver`" — so any package can ship one and apps install it by passing the handle to `<Navigator observers={[...]}>`, with zero Dart edits. See [Navigation → Navigator observers](/docs/building/navigation#navigator-observers) for how consumers use it.

On the JS side, subclass `NavigatorObserverHandle` (itself a `FuseHandle`) so the handle is nominally a navigator observer — this is the type the `observers` prop accepts:

```tsx
import { getOwner, onCleanup } from "solid-js";
import { NavigatorObserverHandle } from "solid-fuse";

export class HeroineController extends NavigatorObserverHandle<"heroineController"> {
  constructor() {
    super("heroineController");
  }
}

export function createHeroineController(): HeroineController {
  const controller = new HeroineController();
  if (getOwner()) onCleanup(() => controller.dispose());
  return controller;
}
```

On the Dart side, wrap your `NavigatorObserver` in a `FuseNavigatorObserverHandle` and register it:

```dart title="dart/lib/src/register.dart"
import 'package:solid_fuse/solid_fuse.dart';

void register(FuseRuntime runtime) {
  runtime.registerHandle(
    'heroineController',
    (node) => FuseNavigatorObserverHandle(node, HeroineController()),
  );
}
```

When the handle is passed to `<Navigator observers={[heroine]}>`, the renderer serializes the reference like any other handle prop, and `FuseNavigatorWidget` resolves each referenced handle's `object` into its `Navigator(observers:)`. The observer lives as long as its handle node is mounted.

<Callout type="info">
Pass a given observer handle to at most one live Navigator — Flutter asserts if
an observer **instance** is attached to more than one at a time.
</Callout>

## ScrollController: the complete example

The built-in `ScrollController` is a good reference for the full pattern:

```tsx title="JS — scroll-controller.ts"
import { createSignal, getOwner, onCleanup } from "solid-js";
import { FuseHandle } from "solid-fuse";

export class ScrollController extends FuseHandle<"scrollController"> {
  readonly scrollOffset: () => number;

  constructor(opts: { initialScrollOffset?: number } = {}) {
    const [scrollOffset, setScrollOffset] = createSignal(
      opts.initialScrollOffset ?? 0,
    );
    super("scrollController", { ...opts, setScrollOffset });
    this.scrollOffset = scrollOffset;
  }

  animateTo(offset: number, opts?: { duration?: number }) {
    return this.call("animateTo", { offset, ...opts });
  }

  jumpTo(offset: number) {
    return this.call("jumpTo", offset);
  }
}

export function createScrollController(
  opts: { initialScrollOffset?: number } = {},
): ScrollController {
  const controller = new ScrollController(opts);
  if (getOwner()) onCleanup(() => controller.dispose());
  return controller;
}
```

```dart title="Dart — scroll_controller.dart"
class FuseScrollController extends FuseHandle<ScrollController> {
  FuseScrollController(FuseNode node)
    : object = ScrollController(
        initialScrollOffset: node.double('initialScrollOffset') ?? 0,
      ),
      super(node) {
    object.addListener(
      () => node.callback('setScrollOffset')?.call(object.offset),
    );
  }

  @override
  final ScrollController object;

  @override
  Future<dynamic> call(String method, dynamic value) async {
    switch (method) {
      case 'animateTo':
        final map = FuseMap.from(value)!;
        object.animateTo(
          map.double('offset') ?? 0,
          duration: Duration(milliseconds: map.int('duration') ?? 300),
          curve: Curves.easeInOut,
        );
      case 'jumpTo':
        object.jumpTo((value as num).toDouble());
      default:
        throw StateError('Unknown scrollController method: $method');
    }
    return null;
  }

  @override
  void dispose() => object.dispose();
}
```
