---
title: Generated components
description: Use Flutter widgets, controllers and your own Dart from JSX without writing a wrapper
---

`fuse gen` reads Dart signatures and writes the wrapper for you: a typed component per widget, a `createX` per controller, and the Dart adapter that reads the props. It covers the long tail (a pub.dev package, a Flutter widget the built-in set doesn't have, your own Dart). It doesn't replace the built-in components: `View`, `Text` and the rest stay the API to reach for first. A generated component mirrors Flutter as it is, so its props have Flutter's names and shapes.

## Setting it up

What crosses to JS is what `dart/lib/fuse.dart` exports. It is an ordinary Dart library, so Dart's own `export`, `show` and `hide` say what goes in:

```dart title="dart/lib/fuse.dart"
export 'package:flutter/widgets.dart' show Padding, Container, ListView, ScrollController;
export 'package:fl_chart/fl_chart.dart';
export 'src/badge.dart';
```

The analyzer and your editor check it, so a misspelled name is an error. Export whole libraries freely: a release build keeps only what the app uses (see below).

`fuse dev` and `fuse build` generate when they start, and `fuse dev` again whenever a Dart file under `dart/lib/` changes (the TypeScript reloads; restart the app for the new adapters). `fuse gen` and `fuse link` do it on their own. When nothing changed, the run takes under half a second. `fuse dev` keeps the generator running, so a run after an edit takes about a tenth of a second. It writes:

- `fuse/<package>.tsx`: one module per Dart package (Flutter's own libraries and `dart:*` go into `flutter`). Import them as `#fuse/<package>`. `fuse gen` adds the `#fuse/*` path to `tsconfig.json`. The values of each class (`EdgeInsets`, `Icons`) are in a module of their own next to it, `fuse/<package>/<Class>.tsx`.
- `fuse/gen-report.txt`: every exported item, and every skipped one with the reason.
- `dart/lib/_generated/fuse.generated.dart`: the adapters. `registerFusePackages` registers them, so the Dart side needs no change.
- `fuse/intrinsics.json` and `fuse/uses.json`: tables for the compile step and for release builds.

All of it can be gitignored: every command that needs it writes it again. The generator runs from the solid-fuse package, so the Dart app needs no extra dependency. Generation is part of the Vite config `fuse` builds, so a Vite setup of your own gets it too.

## Your own Dart

The app's own widgets and controllers cross the same way: export them from `fuse.dart`, or declare them right in it.

```dart title="dart/lib/src/badge.dart"
import 'package:flutter/widgets.dart';

class Badge extends StatelessWidget {
  const Badge({super.key, required this.label, this.count = 0});
  final String label;
  final int count;
  @override
  Widget build(BuildContext context) => Text('$label ($count)');
}
```

```tsx
import { Badge } from "#fuse/my_app";

<Badge label="Inbox" count={3} />;
```

## Packages

A package written for fuse ships a `lib/fuse.dart` of its own, and it is picked up because the app depends on the package: nothing to add to yours. (solid-fuse's own adds the shorthands below.) A package never ships generated code. The app generates it, so it matches the app's solid-fuse and shares one `#fuse/flutter` with everything else. A package that wants a nicer API ships TypeScript on top of its `#fuse/<package>` module.

## Components

A widget becomes a component with the widget's constructor parameters as props. A named constructor gets its own component (`Image.network` is `ImageNetwork`). A `child` or `children` parameter becomes JSX children. Every other parameter is a prop with its Dart name, positional ones too (`Text`'s text is `data`):

```tsx
import { Padding, Text, EdgeInsets } from "#fuse/flutter";

<Padding padding={EdgeInsets.symmetric({ horizontal: 8 })}>
  <Text data="Hello" maxLines={2} />
</Padding>;
```

Some parameters are never props, because Dart supplies them: a `TickerProvider` (`vsync`) gets one from the runtime, and a `BuildContext` (`MediaQuery.removePadding`'s `context`) is the context the widget is built in.

A generic widget is instantiated at its type parameter's bound, `Object?` when it has none, and so is everything generic over that parameter. `DropdownMenu<T>`'s entries take any value:

```tsx
<DropdownMenu dropdownMenuEntries={[DropdownMenuEntry({ value: { id: 7 }, label: "Seven" })]} />
```

A prop that takes a widget takes JSX (`appBar={<AppBar title={<Text>Home</Text>} />}`), and a callback is a function. A callback that returns a `Future` in Dart can return a Promise, and Dart waits for it. Named arguments of a callback arrive as one object after the others: TextField's `buildCounter` is `(context, { currentLength, maxLength, isFocused })` in Dart and `({ currentLength, maxLength, isFocused }) => ...` in JS.

Some props take a particular kind of widget: Scaffold's `appBar` is a `PreferredSizeWidget`, `DropdownButton`'s `items` are `DropdownMenuItem`s. Give them that element; anything else is an error that names both. The parent gets the widget itself, built where the parent is, so it can read it (an app bar's height). The parent rebuilds when that element changes.

### Builders

A callback that returns a value at once, such as `ListView.builder`'s `itemBuilder`, is called synchronously: Dart waits for JS during the frame. A builder returns JSX, or `null` where Dart takes nothing (the end of a list without `itemCount`):

```tsx
import { ListViewBuilder } from "#fuse/flutter";

<ListViewBuilder itemCount={items().length} itemBuilder={(index) => <Text>{items()[index].title}</Text>} />;
```

Each row Flutter builds runs the function in a root of its own, under the component that rendered the list, so context and signals work in it as anywhere else. The row stays reactive, and its root is disposed when Flutter drops the row (it scrolled out, or the list rebuilt). The `BuildContext` argument stays in Dart, so `itemBuilder` gets only `index`.

The function must return without waiting: it can't be `async`, and anything it starts that does wait (a `fetch`) finishes after the row is shown. Keep it short, because the frame waits for it.

## Values

A Dart value is written the Dart way, with builders the module exports:

| Dart | TypeScript |
|---|---|
| `EdgeInsets.all(8)` | `EdgeInsets.all(8)` |
| `BorderRadius.circular(12)` | `BorderRadius.circular(12)` |
| `Colors.red` | `Colors.red` |
| `Point(1, 2)` | `Point(1, 2)` |
| `MainAxisAlignment.center` | `"center"` |

Enums are plain strings. A builder call with only literal arguments is folded into the template at compile time, so it costs nothing at runtime.

A constant is written through its class (`Icons.home`), never as a string: `"Icons.home"` doesn't type-check. That is how a release build knows which ones you use.

A few Dart types have a JS form of their own:

- **Typed data** (`Uint8List`, `Float32List`, `ByteData`, ...) is an `ArrayBuffer` or any view of one (`new Uint8Array(...)`). Dart gives you an `ArrayBuffer`. The bytes cross as they are, not as JSON.
- **A map with keys that aren't strings, numbers or enums** (`Map<ShortcutActivator, Intent>`) is a list of `[key, value]` pairs.
- **A parameter whose default Dart keeps private** (FloatingActionButton's `heroTag`) is optional: leave it out and Dart's default applies.

### Shorthands

Some values have a short form:

| Short form | Means |
|---|---|
| `padding={8}` | `EdgeInsets.all(8)` |
| `borderRadius={12}` | `BorderRadius.circular(12)` |
| `color="#ff8800"` | the CSS hex color (`#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`) |
| `duration={300}` | 300 milliseconds |

A short form works wherever a prop takes that type, or a supertype of it (`padding` takes `EdgeInsetsGeometry`). You can add your own with `@fuseShorthand`. Write a Dart function that takes a `bool`, a number, a `String` or a `List`, and returns the type:

```dart
@fuseShorthand
Offset offsetSquare(double v) => Offset(v, v);
```

A type has at most one shorthand per kind of input. `@FuseShorthand(ts: ...)` narrows the TypeScript type: solid-fuse's color shorthand gives `` r'`#${string}`' ``.

### Implementing a Dart class

Where Dart takes an abstract class (a formatter, a delegate), you can implement it in JS: pass an object literal with a function for each abstract member. Its Dart subclasses still work as values, with their builders:

```tsx
<TextField
  inputFormatters={[
    LengthLimitingTextInputFormatter(20),
    { formatEditUpdate: (oldValue, newValue) => ({ ...newValue, text: newValue.text.toUpperCase() }) },
  ]}
/>
```

Dart calls each function when it needs the member. One that returns a value is called synchronously, like a builder, so it must return at once. A getter is a function without arguments. The object must be a plain object whose functions don't use `this`: a class instance's methods aren't found.

## Controllers: createX

A controller (a Listenable such as `ScrollController`, `TextEditingController` or `AnimationController`, or a class of your own with mutable state) gets a `createX` function per constructor:

```tsx
import { GestureDetector, Text, View } from "solid-fuse";
import { createTextEditingController } from "#fuse/flutter";
import { TextField } from "#fuse/material_ui";

function Search() {
  const query = createTextEditingController({ text: "" });
  return (
    <View>
      <TextField controller={query} />
      <Text>{query.text()}</Text>
      <GestureDetector onTap={() => query.setText("")}>
        <Text>Clear</Text>
      </GestureDetector>
    </View>
  );
}
```

(With `export 'package:material_ui/material_ui.dart' show TextField;` in `fuse.dart`. The import uses the generated component, not the built-in `TextField`.)

- **Options** are the constructor's parameters. Each one takes a value or an accessor. An accessor is read once, unless the controller has a setter of the same name: then it stays in sync.
- **State**: every getter is an accessor (`query.text()`) that updates when Dart notifies. It's `undefined` until Dart first reports it, unless an option or default gives the value.
- **Setters** are `setX(value)`. A simple value (a number, string, boolean or enum) shows up in the accessor at once. A value Dart had before your write arrived is never shown over it, so the cursor of a text field you write to doesn't jump back.
- **Methods** return a Promise of their result (`await anim.forward()` resolves when the animation ends).
- **Streams** are async iterables: `for await (const v of x.changes()) ...`. Leaving the loop cancels the subscription.

A Dart parameter that takes a `TickerProvider` (`vsync`) is supplied for you.

A handle prop only takes controllers that fit: a `ScrollController` can't go where a `TextEditingController` is expected.

### Controllers Dart hands to JS

Dart also gives you controllers: as a callback argument, a getter's value (`ScrollController.position`), or a method's result. You get the same kind of object, with the same state, setters, methods and streams:

```tsx
const scroll = createScrollController();
const at = () => scroll.position()?.pixels() ?? 0;
return <ListView controller={scroll}>...</ListView>;
```

The object is Dart's, so JS never disposes it, and there is no `createX` for a type only Dart makes. The same Dart object always gives you the same JS object, and one you created comes back as itself. You can pass it back to Dart anywhere a controller of its type fits.

### Lifetime

A controller lives as long as the component (the reactive owner) that created it. If something still holds it after that, for example because it was handed to a parent, it lives until nothing does. Then Dart disposes it. There is no `dispose()` method, because anyone holding the controller could call it.

To release one early, give it its own owner and keep the dispose function:

```tsx
import { createRoot } from "solid-js";

const [anim, release] = createRoot((dispose) => [createAnimationController({ duration: 300 }), dispose] as const);
// ... later
release();
```

Only the code that called `createRoot` can release it. To create one that belongs to no component (a module-level controller), use `runWithOwner(null, () => createX())`. It then lives until JS lets go of it.

## Release builds keep what you use

`fuse dev` has every exported widget, controller and constant, so a new one works without a Dart rebuild. `fuse build` keeps only what the bundle uses: after bundling, it writes the Dart adapters again for just those, and Flutter's tree shaker drops the rest of the widgets they would have pulled in. Exporting a whole library costs nothing in the release app. On the demo, exporting all of `widgets` and `material_ui` gives a 15 MB `libapp.so` in full and 6 MB with only what it uses.

What counts as used is what the bundler keeps: an element you render, a `createX` you call, a constant you name. A computed access such as `Icons[name]` keeps every member of `Icons`, as it does in any bundle. A component picked at run time by its tag string is not seen.

`fuse dev` and `fuse gen` write the full adapters again.

## What is skipped

Something that can't cross the bridge yet is skipped, not guessed at, and `gen-report.txt` says why. If an optional parameter is skipped, its prop is missing. If a required one is skipped, the whole widget is missing. Not bridged yet:

- Generic callbacks (`Navigator`'s `pageRouteBuilder`, generic over its own `T`).
- Records, and callbacks whose optional parameters aren't nullable.
- A controller method or setter that takes a function or a widget.
