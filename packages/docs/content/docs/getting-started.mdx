## Prerequisites

- [Node.js](https://nodejs.org/) (or [Bun](https://bun.sh/)) and a package manager (bun, npm, pnpm, yarn)
- [Flutter SDK](https://flutter.dev/docs/get-started/install) 3.50 or newer (Dart 3.14)
- [Rust](https://rustup.rs/) for now: the first build compiles Fuse's JavaScript engine (a few minutes, once)

In an app, `fuse doctor` checks them.

## Create an app

```bash
bun create solid-fuse my-app
# or: npm create solid-fuse@latest my-app
```

It asks for a design (`material`, `cupertino`, `adaptive` or `none`) and the platforms, then writes the app, installs it and runs `git init`. `-y` takes the defaults; `fuse create --help` lists the flags. The app comes with an `AGENTS.md` (and a `CLAUDE.md` pointing at it), so a coding agent knows to read the bundled docs and to check its work in the running app.

```bash
cd my-app
bun dev
```

## Project structure

A Fuse project has JS and Dart side by side:

```
my-app/
  src/
    index.tsx            # Your SolidJS entry point
  dart/
    lib/
      main.dart          # Flutter entry point
      _generated/        # Auto-generated by `fuse link`
    android/ ios/ ...    # Platform folders: Flutter's own
    pubspec.yaml
  fuse.config.ts         # Fuse configuration
  package.json
```

The platform folders are ordinary Flutter ones: edit `Info.plist` or `AndroidManifest.xml` there. `fuse dev` and `fuse build` add the folder of a platform listed in `fuse.config.ts` (`platforms`) when it's missing, with `flutter create`; commit it, and from then on fuse leaves it alone.

## Dart entry point

```dart title="dart/lib/main.dart"
import 'package:flutter/widgets.dart';
import 'package:solid_fuse/solid_fuse.dart';
import '_generated/fuse_packages.dart';

void main() async {
  FuseBinding.ensureInitialized();

  final runtime = await FuseRuntime.create();
  registerFusePackages(runtime);
  await runtime.start();

  runApp(FuseView(runtime: runtime));
}
```

- **`FuseBinding.ensureInitialized()`** — Flutter's binding, plus [Marionette](https://pub.dev/packages/marionette_flutter) in debug and profile builds, so `fuse drive` (or an agent) can tap, type and take screenshots in the running app. See [Developing with agents](/docs/building/agents). Release builds get the plain binding.
- **`FuseRuntime.create()`** — constructs the runtime and initializes FFI. Does **not** start the JavaScript engine yet.
- **`registerFusePackages(runtime)`** — auto-generated by `fuse link`. Calls the `register` function of every Fuse package in your dependencies, wiring up all their widgets, handles, and pages.
- **`runtime.start()`** — starts the JavaScript engine. In debug mode it connects to the Vite dev server for HMR. In release mode it loads a pre-built bundle from Flutter assets. All widget/handle/page registrations must be in place before this runs.
- **`FuseView`** — renders the JS component tree as native Flutter widgets. The app root (`<App>`, `<MaterialApp>`, `<CupertinoApp>`) is in JS, so Dart runs `FuseView` on its own. `FuseView` also works inside a Dart app, as part of a screen.

You can register app-level widgets right after packages, before `start()`:

```dart
registerFusePackages(runtime);
runtime.registerWidget('videoPlayer', VideoPlayer.new);
await runtime.start();
```

## JS entry point

```tsx title="src/index.tsx"
import { MaterialApp } from "@solid-fuse/material";
import { render } from "solid-fuse";
import { Routes } from "#fuse/routes";

render(() => (
  <MaterialApp theme={{ seedColor: "#2563eb" }}>
    <Routes />
  </MaterialApp>
));
```

```tsx title="src/app/index.tsx"
import { Text, View } from "solid-fuse";

export default function Home() {
  return (
    <View padding={24} layout={{ gap: 12 }}>
      <Text fontSize={24} fontWeight={700}>Hello Fuse</Text>
      <Text color="#6B7280">SolidJS inside Flutter</Text>
    </View>
  );
}
```

Each file in `src/app/` is a screen: `src/app/settings.tsx` opens at `/settings`. See [Navigation](/docs/building/navigation#file-routes).

The app root picks the design: `<MaterialApp>` from `@solid-fuse/material`, `<CupertinoApp>` from `@solid-fuse/cupertino`, `<AdaptiveApp>` from `@solid-fuse/adaptive`, or core's `<App>` for no design at all (see [Design packages](/docs/building/design-packages)). `View` and `Text` come from `solid-fuse` and work under any of them. The Solid compiler is pre-configured — you don't need a `vite.config.ts`.

## Running the app

```bash
bun dev
```

This starts Vite and Flutter together. Changes to your JSX hot-reload instantly via HMR.

On a machine with no screen (a cloud agent, CI), `fuse dev --headless` runs the Linux app on a virtual display. See [Developing with agents](/docs/building/agents).

## Using SolidJS

Fuse uses standard SolidJS reactivity. Signals, effects, memos, `Show`, `For`, `Switch` — they all work as expected:

```tsx
import { createSignal, Show, For } from "solid-js";
import { Text, View } from "solid-fuse";

function TodoList() {
  const [todos, setTodos] = createSignal(["Learn Fuse", "Build app"]);
  const [showDone, setShowDone] = createSignal(false);

  return (
    <View layout={{ gap: 8 }} padding={16}>
      <For each={todos()}>
        {(todo) => <Text fontSize={16}>{todo}</Text>}
      </For>
      <Show when={showDone()}>
        <Text color="#16A34A">All done!</Text>
      </Show>
    </View>
  );
}
```
