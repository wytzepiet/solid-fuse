---
title: What is Solid Fuse?
description: SolidJS 2.0 inside Flutter, rendering real Flutter widgets
---

Solid Fuse lets you write an app in [SolidJS](https://www.solidjs.com/) and TSX, and draws it with [Flutter](https://flutter.dev/). There is no webview. Your JSX becomes real Flutter widgets: Flutter's layout, gestures, text, navigation and renderer, on every platform Flutter runs on.

```tsx title="src/app/index.tsx"
import { createSignal } from "solid-js";
import { Pressable, Text, View } from "solid-fuse";

export default function Home() {
  const [count, setCount] = createSignal(0);

  return (
    <View width={Infinity} height={Infinity} layout={{ align: "center", justify: "center", gap: 16 }}>
      <Text fontSize={48}>{count()}</Text>
      <Pressable onPress={() => setCount(count() + 1)}>
        <View padding={{ horizontal: 20, vertical: 12 }} decoration={{ color: "#2563eb", borderRadius: 8 }}>
          <Text color="#ffffff">Add one</Text>
        </View>
      </Pressable>
    </View>
  );
}
```

That file is a page of an app. A signal changes, the one widget that reads it rebuilds, and Flutter draws the frame.

## What you get

- **Solid decides, Flutter draws.** State, effects and async are Solid 2.0, running in a small JavaScript engine on its own thread. Layout and pixels are Flutter's. Neither is watered down.
- **All of Flutter, typed.** Every Flutter widget is a component you can import: `import { ListViewBuilder } from "#fuse/flutter"`. A [pub.dev](https://pub.dev) package is one `export` line away, with no wrapper to write. See [All of Flutter from JSX](/docs/flutter/widgets).
- **No Dart to start.** A new app has one Dart file and you don't edit it. Dart is there when you want it: [your own widgets](/docs/flutter/your-own-dart) cross to JSX the same way Flutter's do.
- **An agent can run it.** Flutter runs on Linux, so a coding agent on a cloud machine with no screen can start your mobile app, tap through it and look at screenshots. That is built in. See [Agents](/docs/agents).
